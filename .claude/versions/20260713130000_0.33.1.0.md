# Versão 0.33.1.0 — idioma-alvo da tradução vem das preferências (não da URL)

**Data:** 2026-07-13

Correção da rota de tradução, notada logo após a 0.33: passar o idioma-alvo na URL virou redundante
quando ele já mora nas preferências do usuário. A rota deixou de **requerer** o idioma; agora lê o
alvo direto do `language_to_translate` do JWT.

## Corrige uma premissa errada da 0.33

Na 0.33 (Opção A) tratamos `language_to_translate` como **só dica de client** que **não afeta a API**,
e a tradução ficou **sem gate**. A 0.33.1 conserta isso: o campo é a **fonte autoritativa** do alvo
da tradução — a **API decide** o comportamento a partir dele; o client apenas altera o valor para o
usuário. Consequência: o campo **volta a afetar** a resposta da API, e o `null` reintroduz um gate
(agora pelo campo certo).

Motivo (do Nathan): "A API precisa sim tomar decisões com essa opção, enquanto o client apenas altera
ela pro usuário." Foi isso que revelou que a redação "não afeta a API" da 0.33 estava errada.

## Mudanças

- **Rota**: `GET /v1/articles/{id}/translate/{language}` → `GET /v1/articles/{id}/translate` (sem o
  param de idioma). `main.go` e os apps de teste atualizados.
- **Endpoint** (`services/endpoints/v1/articles/translate.go`): o alvo deixa de vir de
  `c.Params("language")` e passa a vir de `claims.LanguageToTranslate` (JWT). Regras:
  - `language_to_translate` nulo (sem alvo configurado) → **400** (`no translation target configured`).
  - alvo inválido (defensivo, JWT é confiável mas validamos) → 400.
  - alvo == `language_original` → 400; `language_original` null → 400 (inalterado).
  - `ai_personality` (do JWT) segue ajustando o tom; read-only; re-sanitiza a saída (bluemonday).

## Como testar manualmente

1. `ENVIRONMENT=development task ls`; `task sdfull` (o dev vem com `language_to_translate=pt`).
2. `GET /v1/articles/{id}/translate` (sem idioma na URL) traduz para o `language_to_translate` do token.
   Requisição pronta no Bruno: `articles/translate` (só o `:id`).
3. `PUT /v1/users/me/preferences` com `{"language_to_translate": null, ...}`, pegue o novo token e
   chame a tradução → **400** (sem alvo). Com `"en"`, volta a traduzir para inglês.
