# Versão 0.36.0.1 — doc de integração para o web client

**Data:** 2026-07-13

Atualização **docs**. Novo arquivo `.claude/memory/client-integration.md`, feito para ser enviado ao
projeto do web client **junto com `endpoints.md`**.

Motivo: o `endpoints.md` cobre os shapes das rotas, mas o client precisava das **filosofias e contratos**
da API — em especial (pedido do Nathan) o **contrato de renderização do conteúdo** (o que a sanitização
deixa passar: tags, links internos/externos, imagens, embeds YouTube/Twitch, Instagram→link, e o que
NUNCA aparece) e o **julgamento** (como uma notícia entra num feed, não-retroatividade).

Conteúdo do arquivo (recorte do que afeta o client, cruzando com `endpoints.md`/`PROJECT.md`):

1. Renderização do `content` (HTML sanitizado): whitelist de tags/atributos, links internos
   (`CLIENT_URL/articles/{id}`) vs externos, imagens externas (nota de privacidade), embeds
   YouTube/Twitch, Instagram vira link; **sem `class`/`style`/`id`** → estilizar por tag.
2. Julgamento (keywords + IA, não-retroativo, máx. 5 feeds).
3. Sessão/auth (redirect OAuth com tokens no fragment, refresh, claims do token, regeneração ao mudar prefs).
4. Abrir notícia + marcação de leitura (`PUT /articles/:id/read`, 200/204/404) e notícia global vs `is_read`.
5. Tradução (alvo vem do `language_to_translate` do token; client decide mostrar; cache no client; 400s).
6. Preferências (`language_to_translate` anulável, `ai_personality`; tema é do client).
7. Feeds (tela principal `GET /feeds/:id/articles`; poll `check-for-new-articles`; feeds por-usuário).
8. Convenções (UTC, paginação, erros, manutenção 503, CORS Bearer).

Sem mudança de código. `endpoints.md` já se declarava consumível pelo client (cabeçalho) — este arquivo
o complementa. Manter em sincronia com a API é responsabilidade do time da API.
