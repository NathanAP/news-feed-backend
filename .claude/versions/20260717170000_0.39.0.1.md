# 0.39.0.1 — Keywords nos artigos de exemplo do seed

Follow-up direto da 0.39.0.0. Ao smoke-testar a sugestão de keywords no dev, o endpoint respondia
sempre vazio: os artigos de exemplo (`cmd/seed/examples.json`) **não tinham keywords**, então
`task sda` populava o banco com todos os `keywords` em `[]`. Não era bug do endpoint (pool sem
keywords → sugestão vazia é o comportamento correto), mas deixava a feature nova sem como ser testada
manualmente em dev sem rodar a descoberta de verdade.

## O que mudou

- `cmd/seed/examples.json`: cada um dos 20 artigos de exemplo ganhou um campo `keywords` com termos em
  **inglês minúsculo**, misturando específicos (banda/pessoa do título: `metallica`, `megadeth`,
  `dave mustaine`, `iron maiden`, `rush`...) e genéricos (`rock`, `metal`, `music`, `live show`,
  `tour`...), respeitando o mínimo de 5 por artigo (regra do `PROJECT.md`). Os genéricos recorrem de
  propósito, então `popular` tem vencedores claros e `related` a partir de um genérico traz sinal útil.
    - Os termos também dão overlap com as keywords dos feeds de exemplo (`rock`, `metal`, `metallica`,
      `kamelot`), então o **julgamento** também passa a associar artigos aos feeds em dev, não só a
      sugestão.
    - Nenhuma outra parte do `examples.json` foi tocada (títulos/acentos preservados, verificado byte a
      byte); a struct `exampleArticle` já tinha o campo `Keywords`, então nenhum código Go mudou.

## Banco de dev já existente

O banco estava de pé com artigos de keywords vazias (3 execuções antigas do `sda`, 60 linhas). Em vez
de exigir um `task sda` novo, os registros existentes foram atualizados no lugar por um `UPDATE ...
WHERE title = ...` gerado a partir do mesmo `examples.json` (match por título, que o seed grava
verbatim). Resultado verificado: 60/60 artigos com keywords, e o endpoint `GET
/v1/feeds/keyword-suggestions` respondendo popular e related corretamente contra a API real.

## Versionamento

Incremento de tier `docs` (0.39.0.0 → 0.39.0.1): é dado de seed de desenvolvimento, não muda o
contrato nem o comportamento da aplicação. Não requer rotina de testes completa (o `cmd/seed`
tem teste próprio, que passou; ele usa fixtures inline, não o `examples.json`).

## Como testar

```bash
task sda    # (re)popula os artigos — agora com keywords
```
Depois, com um token (`task sdl`):
- `GET /v1/feeds/keyword-suggestions` → `strategy: popular`, com `rock`/`music`/`metal` no topo.
- `GET /v1/feeds/keyword-suggestions?keywords=metal` → `strategy: related`, trazendo co-ocorrentes
  (`rock`, `thrash metal`, `dave mustaine`...) sem devolver `metal`.
