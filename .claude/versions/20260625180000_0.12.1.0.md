# Versão 0.12.1.0 — Fix: unicidade ignorava soft-delete em `sources`

**Data:** 2026-06-25
**Tipo:** patch (bug encontrado em uso real)

## O bug

Ao tentar criar uma fonte com a mesma `url`/`url_rss` de uma fonte previamente **soft-deletada** (`status = 0`, `removed_at` preenchido), a API retornava **409 Conflict** ("source with this URL already exists").

Causa: as constraints `UNIQUE (url)` e `UNIQUE (url_rss)` definidas inline na tabela `sources` (criada na 0.11.0.0) são aplicadas pelo SQLite contra **todas** as linhas, inclusive as soft-deletadas. Isso fazia um registro inativo **bloquear uma operação ativa** — violação direta da convenção de status consolidada na 0.12.0.0 (registros inativos não podem afetar operações ativas).

## A correção

Substituição das constraints `UNIQUE` inline por **índices únicos parciais** com `WHERE removed_at IS NULL`. A unicidade passa a valer apenas entre registros ativos; um registro soft-deletado deixa de bloquear a criação de um novo registro com a mesma URL.

### Migração
- `migrations/20260625180000_sources_partial_unique_index.sql`
    - SQLite não permite dropar uma constraint inline, então a tabela é **reconstruída** (cria `sources_new` sem as constraints, copia os dados, dropa a antiga, renomeia) e os índices parciais são criados:
        - `idx_sources_url_active` em `url` `WHERE removed_at IS NULL`
        - `idx_sources_url_rss_active` em `url_rss` `WHERE removed_at IS NULL`
    - `down` reverte para o estado anterior (constraints inline).

### Schema
- `schema.sql` atualizado: tabela `sources` sem as constraints inline + os dois índices parciais.

### Comportamento preservado
- Duas fontes **ativas** com a mesma `url`/`url_rss` continuam rejeitadas com 409 (o índice parcial cobre as linhas ativas). O controller continua detectando `"UNIQUE constraint failed"`, que também é a mensagem emitida em violação de índice parcial.

## Documentação

- `PROJECT.md`, seção *Exclusão de registros*: adicionadas duas regras generalizáveis para tabelas futuras:
    - registros soft-deleted não podem "bloquear a criação de novos registros através de constraints de unicidade";
    - constraints de unicidade devem ser índices únicos parciais com `WHERE removed_at IS NULL`.
