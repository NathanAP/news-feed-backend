# v0.10.0.0 — User preferences

## What was done
Implemented the full user preferences feature: migration, controller, JWT claims update,
two new API endpoints, and tests across all three layers.

### Migration
- `20260624120000_create_user_preferences_table.sql` — creates `user_preferences` table
  with `id`, `user_id`, `status`, `theme`, `language`, `translate_content`,
  `ai_personality`, `created_at`, `modified_at`, `removed_at`.
- Same migration seeds default preferences for any existing users in the DB.
- `schema.sql` updated.

### New: `schemas/user_preferences.go`
- `Theme` enum: `light` | `dark`
- `Language` enum: `pt`, `en`, `es`, `fr`, `de`, `it`, `ja`, `zh` (each with `IsValid()`)
- `AIPersonality` enum: `fun` | `informative` | `mixed`
- `UserPreferencesResponse` DTO
- `UpdateUserPreferencesRequest` DTO

### New: `services/controllers/user_preferences.go`
- `CreateDefault(ctx, userID)` — creates preferences with project defaults (dark/pt/true/mixed)
- `FindByUserID(ctx, userID)` — fetches active preferences
- `Update(ctx, userID, params)` — updates all preference fields
- `SoftDelete(ctx, userID)` — called by UserController.SoftDeleteUser

### Updated: `services/controllers/interfaces.go`
- Added `UserPreferencesControllerInterface`
- Updated `AuthControllerInterface`: `GenerateAccessToken` now takes `db.UserPreference`;
  added `RegenerateFromClaims`

### Updated: `services/controllers/users.go`
- Constructor now accepts `UserPreferencesControllerInterface`
- `CreateUser` creates default preferences after user creation (per convention)
- `SoftDeleteUser` also soft-deletes preferences

### Updated: `services/controllers/auth.go`
- Constructor now accepts `UserPreferencesControllerInterface`
- `GenerateAccessToken(user, refreshTokenID, prefs)` — includes preference fields in Claims
- `HandleGoogleCallback` fetches preferences to include in JWT
- `RefreshAccessToken` fetches preferences to include in JWT
- Added `RegenerateFromClaims` — used by PUT preferences to issue updated token

### Updated: `schemas/auth.go`
- `Claims` now includes: `Theme`, `Language`, `TranslateContent`, `AIPersonality`

### New endpoints
- `GET /v1/users/me/preferences` — reads directly from JWT Claims (no DB hit)
- `PUT /v1/users/me/preferences` — validates fields, updates DB, returns new `access_token`
  and updated preferences in response

### Bruno
- `bruno/users/get-preferences.bru`
- `bruno/users/update-preferences.bru` (with accepted values documented)

### Tests
- Unit (6 tests): GET success/unauth, PUT valid/invalid theme/language/ai_personality/missing body/unauth
- Integration (4 tests): GET returns defaults, GET unauth, PUT persists and returns new token, PUT invalid theme
- E2E (4 tests): GET after login has defaults, PUT updates and new token has updated prefs, invalid values, unauth
- `tests/mocks/services/jwt.go` updated — `GenerateTestAccessToken` accepts optional `prefs` (variadic)
- `tests/fixtures/user_preferences_fixtures.go` added

## Key decisions
- `UserController.CreateUser` creates preferences internally — any code path creating a
  user gets preferences automatically, per the controller convention.
- `UserController.SoftDeleteUser` soft-deletes preferences in the same call.
- GET reads from Claims with zero DB queries — preferences are always in the token.
- PUT issues a new `access_token` so clients get updated preferences without re-login.
- UUID v4 format used in migration seed (SQLite has no UUID v7 function); app code continues
  to use UUID v7 for all new records.
