# Versão 0.24.0.0 — paginação global + arrumação de código

**Data:** 2026-07-02

Versão de **organização + paginação**. Sem schema novo, sem IA, sem dependência nova. Três frentes:
renomear `judgment`→`judgement`, mover os enums para um pacote único, e implementar paginação nas
rotas de coleção.

## 1. Rename `judgment` → `judgement`

Corrige a inconsistência: rota/env/prompt já eram "judgement" (com E), mas o pacote Go era `judgment`.
- Pasta `services/judgment/` → `services/judgement/` (arquivo `judgment.go` → `judgement.go`, `package
  judgement`, tipo `judgement.Evaluator`).
- `services/ai/judgment.go` → `services/ai/judgement.go` (+ `_test.go`) — `ParseScore` (sem mudança de
  conteúdo, só o nome do arquivo).
- Referências atualizadas em `main.go`, `discovery/processor.go` e testes.

## 2. Enums em local comum (`schemas/enums/`)

- Novo pacote `schemas/enums/` com um arquivo por enum: `theme.go`, `language.go`, `ai_personality.go`.
  `Language` saiu de `schemas/language.go`; `Theme`/`AIPersonality` saíram de `user_preferences.go`.
- Referências passaram de `schemas.X` para `enums.X` em todo o código (schemas DTOs, middlewares,
  endpoints, controllers, mock de JWT). Sem ciclo: `schemas → enums` é mão única.
- **Por que `services/langdetect`/`sanitize` têm `_test.go`?** (dúvida do ROADMAP) São pacotes de
  **lógica pura** (sem banco/rota); teste co-localizado é o idiomático — mesmo padrão de `services/ai`.
  Documentado no `conventions.md`.

## 3. Paginação (`services/pagination` + rotas de lista)

- Pacote novo `services/pagination`: `Params`, `Meta`, `Response[T]` (genérico), `ParseParams(page,
  page_size)` (com defaults/clamps) e `Paginate[T](items, params)`.
- Query: `?page=` (mín/padrão 1) e `?page_size=` (mín 1, máx 100, padrão 20) — valores inválidos caem
  no default/clamp, nunca erro.
- Resposta: `{ docs: [...], pagination: { actual_page, total_pages, actual_count, total_count,
  has_next_page, has_previous_page } }` (formato do `PROJECT.md`). Página fora do range → `docs` vazio,
  `actual_page` fica no valor pedido, sem erro.
- Aplicada em `GET /v1/articles`, `/v1/sources`, `/v1/feeds` (2 linhas por handler: parse + wrap).
- **Decisão — paginação em memória**: os handlers de lista já carregam todas as linhas e **filtram em
  Go**; a paginação fica na mesma camada (fatia a lista filtrada). Consistente e mínima. Se o volume
  crescer (pós-Postgres), migrar para `LIMIT/OFFSET` em SQL — anotado.
- **Quebra de contrato**: as 3 rotas de lista deixaram de retornar array cru e passaram a devolver o
  envelope. Todos os testes de lista (unit/integração/e2e) foram ajustados (helper `decodePage` por
  pacote de teste, lê `docs`).

## Testes
- **Unit** `services/pagination`: `ParseParams` (defaults, inválido, clamps, negativos) e `Paginate`
  (primeira página, última parcial, fora do range → vazio, entrada vazia, metadados).
- **Integração** (`tests/integration/api/articles/pagination_test.go`): 5 artigos, verifica
  `page`/`page_size`, metadados, página fora do range e defaults, com DB real.
- Todos os testes de lista existentes adaptados ao envelope. `go vet ./...` limpo e `go test ./...`
  sem falhas (49 pacotes).

## Como testar
- **Bruno**: `List Articles`/`List Sources`/`List Feeds` ganharam `page`/`page_size` opcionais.
  Ex.: `/v1/articles?page=2&page_size=10`. A resposta agora é `{ docs, pagination }`.
- **Automatizado**: `task ta` (ou `go test ./...`).

## Observação para clients
- Consumidores das rotas de lista precisam ler `resp.docs` (antes era o array na raiz) e podem usar
  `resp.pagination` para navegar.
