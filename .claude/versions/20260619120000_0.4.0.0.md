# v0.4.0.0 — Google OAuth2 + JWT authentication

## What was done
Full authentication system with Google OAuth2, JWT access tokens, and refresh tokens.

### New dependencies
- `golang.org/x/oauth2` — Google OAuth2 flow.
- `github.com/golang-jwt/jwt/v5` — JWT generation and validation.

### Database
- Migration `20260619130000_create_refresh_tokens_table.sql`: `id`, `user_id`, `status`, `expires_at`, `created_at`, `modified_at`, `removed_at`.
- `schema.sql` and `sqlc` updated with refresh_token queries.
- The `id` field of the refresh_token IS the token value sent to the client — no separate token column.

### Schemas
- `schemas/auth.go`: `Claims` (JWT), `AuthResponse`, `RefreshRequest`.
- `schemas/users.go`: `UserResponse` DTO.

### Controllers
- `services/controllers/refresh_tokens.go`: Create, FindByID (with expiry check), Extend, Revoke, RevokeAll.
- `services/controllers/auth.go`: HandleGoogleCallback, RefreshAccessToken, GenerateAccessToken.

### Middleware
- `middlewares/auth.go`: validates JWT signature + checks refresh_token in DB on every protected request (1 DB query).

### Endpoints
- `GET /v1/auth/google` — redirects to Google consent screen.
- `GET /v1/auth/google/callback` — exchanges code, creates/finds user, issues tokens.
- `POST /v1/auth/refresh` — renews access_token and extends refresh_token expiry.
- `POST /v1/auth/logout` — soft-deletes refresh_token.
- `DELETE /v1/auth/invalidate` — revokes a specific refresh_token (open, admin later).
- `DELETE /v1/auth/invalidate-all` — revokes all tokens for a user (open, admin later).
- `GET /v1/users/me` — returns authenticated user data from JWT claims.

## Key decisions
- Single session policy: login invalidates all existing active refresh_tokens for that user.
- `GOOGLE_REDIRECT_URL` added to `.env` and `.env.example`.
- JWT claims include: `user_id`, `email`, `name`, `picture`, `refresh_token_id`, `created_at`.
- Middleware validates the refresh_token in DB on every request to detect revoked sessions.
