# Versão 0.19.0.0 — descoberta de notícias (CRON) + rota de teste + prompts

**Data:** 2026-06-30

## Resumo

Pipeline de **descoberta de notícias** via CRON interna: a cada tick, varre as sources ativas,
faz parsing do RSS de cada uma com `gofeed`, filtra o que é "novo" pelo watermark
`system.last_article_discovery_at` e entrega os itens a um **Processor** (seam para a 0.20).
Nesta versão **nada é persistido** (opção 1A acordada no planejamento): a descoberta apenas
busca e reporta. Inclui a rota de teste dry-run `GET /v1/sources/{id}/discovery` e os prompts
que a 0.20 usará no tratamento/julgamento.

## Decisões aplicadas

- **Descobrir sem persistir (1A).** Articles exige `content`+`keywords`, que só nascem com a IA
  da 0.20. Logo a 0.19 só descobre/reporta; persistência + tratamento + julgamento vão para a
  0.20 através da interface `discovery.Processor` (hoje `NoopProcessor`).
- **Watermark como dedup entre runs.** "Novo" = publicado após `last_article_discovery_at`.
  Primeira run (watermark vazio) → tratado como `now()` para não superlotar a futura fila de
  tratamento (regra do `PROJECT.md`). Item **sem data** sempre entra (dedup real por
  `url_original` virá com a persistência na 0.20).
- **CRON no start/stop da app**, gated por `RSS_FEED_CRON_ACTIVE`; agenda em
  `RSS_FEED_CRON_SCHEDULE` (`robfig/cron/v3`). Logs da CRON gated por `RSS_FEED_CRON_VERBOSE_MODE`
  (independente do `VERBOSE_MODE` global → novo `logger.Print`).
- **CRON checa `app_status`**: pula a run em manutenção (o guard HTTP não cobre job interno).
- **Resiliência:** fetch com retry/backoff (`sethvargo/go-retry`); falha de uma source é isolada
  (não aborta a varredura). Network fora de transação; leituras/escrita do watermark via `runTx`.
- **Rota de teste = dry-run** (`GET /v1/sources/{id}/discovery`): não grava nada nem avança o
  watermark. Query opcional `last_article_discovery_at` (RFC3339 UTC) sobrepõe o limite inferior
  para testar sem esperar notícia nova. Aberta (admin-futuro), sob o guard de manutenção.

## O que foi feito

### Dependência
- `github.com/robfig/cron/v3` adicionado; `sethvargo/go-retry` promovido a dependência direta.

### SQLC / controller
- `sqlc/queries/system.sql` + `system.sql.go`: `UpdateSystemLastArticleDiscovery` (+ `querier.go`).
- `services/controllers/system.go` — `UpdateLastArticleDiscovery(ctx, q, at)`; interface atualizada.

### Serviço de descoberta — `services/discovery/`
- `DiscoveredArticle` (item cru: title, content, url_original, published_at, source_id).
- `Processor` (seam) + `NoopProcessor` (0.19 não persiste).
- `EffectiveSince(watermark, now)` — vazio → `now()`.
- `DiscoverFromSource(ctx, client, source, since)` — gofeed + filtro por data (item sem data
  entra) + retry/backoff.

### CRON — `services/cron/`
- `DiscoveryRunner.Run`: lê app_status + sources + watermark → descobre por source (isolando
  falhas) → `Processor.Process` → escreve watermark. Logs gated por verbose.
- `Scheduler` (start/stop) sobre `robfig/cron/v3`.

### Endpoint / schema
- `services/endpoints/v1/sources/discovery.go` — `GET /v1/sources/:id/discovery` (dry-run).
- `schemas/sources.go` — `DiscoveredArticleResponse`, `SourceDiscoveryResponse`.

### main.go
- Cliente HTTP dedicado (timeout 30s); rota `/:id/discovery` registrada; scheduler iniciado no
  boot quando `RSS_FEED_CRON_ACTIVE=true`.

### Logger
- `logger.Print` — impressão colorida incondicional (para flags próprias como a da CRON).

### Prompts — `services/prompts/`
- `article_treatment.yaml`, `article_keywords.yaml`, `article_feed_judgment.yaml` (inglês). Serão
  usados na 0.20. Tradução/resumo ficam para a 0.21.

### Testes
- `tests/mocks/external/rss_client.go` — `SampleRSSFeedDated` (itens datados + um sem data).
- **Unit** (`tests/unit/sources/discovery_test.go`): itens novos, feed vazio (200 `[]`), 404,
  401, data inválida (400), erro de feed (500).
- **Integração** (`tests/integration/api/sources/discovery_test.go`): dry-run retorna itens **sem
  alterar DB/watermark**; sem override usa watermark (NULL→now→só item sem data); 404.
- **Integração CRON** (`tests/integration/cron/discovery_test.go`): descobre e avança watermark
  (sem persistir); pula quando app off.
- **E2E** (`tests/end-to-end/api/sources/discovery_flow_test.go`): login → cria source → dry-run.

### Bruno / controle
- `bruno/sources/source-discovery.bru`. `.env.example`/`ROADMAP` → 0.19.0.0; itens marcados.
