# Versão 0.34.0.0 — tratamento de notícias, Fase 1: a IA sai do corpo

**Data:** 2026-07-13

Primeira das três fases da reforma do tratamento de notícias (0.34 Fase 1 · 0.35 URLs · 0.36 embeds).
A grande virada de filosofia: **a IA nunca mais reescreve o corpo da notícia**. O corpo passa a ser o
HTML **original do RSS**, limpo de forma **determinística** pelo `bluemonday`. A IA fica só para
keywords e julgamento.

## Por quê

O `Treater` LLM (0.20/0.21) reescrevia o corpo "só na forma", mas isso é caro, não-determinístico e
arrisca alucinação no corpo. Substituído por sanitização determinística. O `bluemonday` deixa de ser
uma **rede de segurança sobre a saída do LLM** e vira o **estágio primário** de limpeza, aplicado
direto ao RSS cru.

## Pipeline: antes → depois

Antes: `dedup → Treater(LLM)+sanitize → keywords → langdetect → persist → judge`
Depois: `dedup → langdetect(cru) → sanitize(bluemonday) → keywords → persist → judge`

## Sanitizador novo (`services/sanitize`)

Deixou de ser decorator do `Treater`; agora é a função de pacote `Sanitize(html)` aplicada ao corpo
cru. Política **permissiva-porém-segura** (bem mais rica que a anterior "só tags básicas"):

- **Permite:** formatação ampla (texto, títulos `h1`–`h6`, listas, tabelas, `figure`/`figcaption`,
  `blockquote`, `code`/`pre`, etc.) + `<a href>` (esquemas `http`/`https`/`mailto`, `rel=nofollow`) +
  `<img src>` (esquemas `http`/`https`, com `alt`/`width`/`height`).
- **Bloqueia (invariantes de segurança):** nunca `<script>`, nunca `on*`, nunca `<style>`, nunca
  `<iframe>` (embeds ficam pra 0.36). Também remove `class`/`style`/`srcset` e tags/atributos desconhecidos.
- Tags fora da whitelist são desembrulhadas (texto fica, tag some); conteúdo de `script`/`style`/`head`/
  `iframe`/`noscript` é dropado inteiro (não vaza como texto).

> Nesta fase os embeds (YouTube/Twitch iframe, Instagram script) são **removidos** — resultado seguro;
> a restauração (iframe allowlist + Instagram→link) vem na 0.36.

## Dry-run `POST /v1/articles/treatment`

Sem passo de LLM no corpo: agora detecta idioma + **sanitiza** (determinístico) → keywords.
`content` na resposta é o corpo sanitizado; `treatment_ms` passou a medir a sanitização (mantido de
propósito, vai incorporar o tratamento de URLs na 0.35). 500 só em falha da IA de keywords.

## Como testar manualmente

1. `ENVIRONMENT=development task ls`; `task sdfull` para token.
2. `POST /v1/articles/treatment` com um `content` cheio de HTML de RSS (o exemplo no Bruno tem `<iframe>`
   do YouTube, `<script>`, `class`/`style`/`srcset`): a resposta `content` volta **sanitizada** —
   `<a href>`/`<img>`/formatação ficam; iframe/script/atributos perigosos somem. Sem chamada de LLM no corpo.
3. (dev) Rodar a CRON/discovery numa source real e conferir no `sqlite-web` que `articles.content` está
   sanitizado (e não reescrito por IA).
