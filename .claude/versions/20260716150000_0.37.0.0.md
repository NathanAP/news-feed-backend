# 0.37.0.0 — PostgreSQL 18 no lugar do SQLite

Troca do motor do banco. O SQLite sempre foi o desvio: a stack em `CLAUDE.md` já declarava
PostgreSQL + pgadmin4, e a pasta `pgadmin4/` existia vazia desde o início. Esta versão converge para
o que já estava escrito.

**O contrato da API não mudou.** O `status` nunca foi exposto como filtro e o `int` já era convertido
para bool nos schemas de resposta, então client e coleção do Bruno seguem intactos. Foi cirurgia
interna — com uma exceção, o formato das datas, descrita abaixo.

Executada em 3 etapas (a 4ª ficou registrada no ROADMAP como dívida assumida).

## Decisões

- **Dados descartáveis**: banco novo do zero, sem ETL. Nenhum ambiente havia sido publicado.
- **Migrações recomeçadas**: as 13 migrações SQLite foram apagadas e substituídas por uma única
  inicial PG-native (`20260716120000_initial_schema.sql`). Sumiu a dança de recriar tabela do
  `sources_partial_unique_index` (o SQLite não faz `ALTER`; o PG faz índice parcial nativo).
- **Driver `pgx/v5/stdlib` via `database/sql`** (`sql_package: "database/sql"` no sqlc), não pgx
  nativo. Mantém `*sql.DB`, `sql.NullString`/`sql.NullTime` — `transaction.go`, a interface `Querier`
  e os mocks ficaram **intactos**. Migrar para pgx nativo (`pgtype.*`) depois é uma linha no
  `sqlc.yaml` + regen; a performance do protocolo binário não se paga no volume atual.
- **sqlc mantido.** Postgres é o engine mais forte dele (o suporte a SQLite é o mais fraco em
  inferência de tipo); sair para um ORM contrariaria a convenção de tipagem forte e SQL explícito, e
  custaria reescrever 42 queries + controllers + mocks.
- **Tipos**: `status`/`is_read`/`app_status` → `BOOLEAN`; datas → `TIMESTAMPTZ`; `keywords` → `JSONB`
  (+ índice GIN). `id` segue `TEXT` — o tipo `uuid` nativo ripplearia por todo model/teste e fica para
  uma versão própria.
- **Docker obrigatório só para o banco.** A API continua rodando no host (`task ls`) ou no compose
  (`task ds`). Rodar a API sempre em container tornaria o loop de desenvolvimento um rebuild de imagem
  por alteração, sem ganho.

## Etapa 1 — a aplicação roda

- `docker-compose.yaml`: saiu `sqlite-web` e o bind-mount `./db`; entraram `postgres:18-alpine`
  (volume `postgres_data`, healthcheck `pg_isready`) e `pgadmin4` (`:5050`, servidor pré-registrado via
  `pgadmin4/servers.json`, sem senha — o arquivo é versionado). A API só inicia com o banco healthy
  (ela migra no boot). O compose sobrescreve a `DATABASE_URL` do `.env` (que aponta para `localhost`)
  com o host `postgres` da rede interna, então o mesmo `.env` serve aos dois modos.
- `.env.example`: `DATABASE_URL` (DSN único — é o formato que Supabase/Neon entregam, então apontar
  para um banco hospedado vira config, não código) + `POSTGRES_*` (init do container) + `PGADMIN_*`.
- `migrations/` + `schema.sql`: migração inicial única.
- `sqlc.yaml`: `engine: postgresql`. Queries reescritas: `?` → `$N`, `status = 1` → `= TRUE`,
  `is_read = 1` → `= TRUE`.
- **`json_each` → `jsonb_array_elements_text`** em `FindCandidateFeedsByKeywords` (camada 1 do
  julgamento) — a única tradução não-mecânica. O lado do feed usa `CROSS JOIN LATERAL` (é o `LATERAL`
  que permite a expansão referenciar a linha do feed); o lado da notícia é join comum, com
  `sqlc.arg(keywords)::jsonb` para o parâmetro sair nomeado.
- `main.go`: driver pgx, `DATABASE_URL`, fora o `os.MkdirAll("db")` e os pragmas WAL/busy_timeout,
  goose com dialeto `postgres`.
- `sqlite_errors.go` → **`postgres_errors.go`**: `*pgconn.PgError` + SQLSTATE `23505`. Segue tipado
  (nunca por texto do erro) — o `errors.As` alcança o erro do pgx através do `database/sql`.
- Ripple `int` → `bool` (19 sites) e `keywords` `string` → `json.RawMessage`. Três viraram
  **simplificação**: `UpdateAppStatus` e `SetAppStatus` perderam a conversão manual 0/1, e o
  `encodeKeywords` deixou de fazer cast (o `json.Marshal` já devolve `[]byte`).
- `cmd/seed`: driver/dialeto puxados da Etapa 3 para cá — sem isso o `task sdfull` não rodava e não
  havia como verificar a etapa.

### Bug encontrado na verificação: datas fora de UTC

O pgx materializa `TIMESTAMPTZ` em `time.Local`, então a API passou a serializar
`2026-07-16T15:01:13-03:00` em vez de `...Z` — instante certo, representação errada, **variando
conforme o host**, contra a convenção de datas. `timezone=UTC` no DSN **não resolve** (muda a sessão
do servidor, não o fuso em que o pgx materializa o valor em Go). Corrigido com
`time.Local = time.UTC` no `main.go` e no seed, antes de qualquer conexão.

É mutação de global do runtime e a garantia fica implícita. Trocar por garantia no tipo (`utctime.Time`
com `Scan`/`MarshalJSON` via `overrides` do sqlc) é a **Etapa 4**, registrada no ROADMAP.

## Etapa 2 — os testes voltam

- `tests/utils/db.go` reescrito: o Postgres não tem modo em memória, então a regra de isolamento é
  cumprida com **banco temporário de verdade**. Um container `postgres:18-alpine` descartável
  (testcontainers) serve a execução inteira; as migrações rodam **uma vez** num database template e
  cada teste **clona** o template (`CREATE DATABASE ... TEMPLATE` — cópia de arquivo dentro do
  servidor, microssegundos em vez da migração inteira), dropado com `WITH (FORCE)` no fim.
- Container **compartilhado**, não um por pacote: o `go test` roda cada pacote num processo separado e
  em paralelo — sem isso seriam 14 Postgres simultâneos. A criação do template é serializada entre
  processos por um **advisory lock** do próprio Postgres. O reaper do testcontainers destrói o
  container ao fim: nada sobra na máquina. `task test-db-clean` só serve para container órfão de
  execução interrompida.
- Regra de teste do `conventions.md` reescrita: "instância em memória por teste" → "banco temporário
  por teste, descartado ao fim". Intenção (isolamento total) preservada; registrado que **testes agora
  exigem Docker**.
- `modernc.org/sqlite` removido do `go.mod` e de todos os imports. Não há mais uma linha de SQLite.
- Fixtures, mocks e testes ajustados para `bool` / `json.RawMessage`.

### Duas descobertas dos testes

- **JSONB normaliza o JSON.** Gravamos `["alpha","beta"]` e o PG devolve `["alpha", "beta"]` — ele
  guarda a estrutura parseada e re-renderiza. Um teste comparava os bytes crus e quebrou; virou
  `assert.JSONEq`. A asserção antiga testava um detalhe de implementação que nunca foi nosso.
- **`assert.Equal(t, int64(1), user.Status)` compila e falha em runtime**, porque `assert.Equal`
  recebe `any`. Duas escaparam do compilador e só o teste rodando pegou.

Suíte: **30 pacotes verdes, ~40s a frio** (sem container e sem cache). Era milissegundos com SQLite em
memória — custo assumido.

## Destrava

Com o Postgres cai o teto de single-writer do SQLite: escrita concorrente real, `DISCOVERY_CONCURRENCY > 1`
de verdade, múltiplas réplicas e a seção "Escalabilidade futura" (fila + workers) do ROADMAP. E, para o
deploy, a API deixa de precisar de disco persistente e de instância única — com o banco externo
(Supabase/Neon), hospedagens de free tier voltam a ser viáveis.

## Fora do escopo

Filtragens e paginações que hoje acontecem em Go em vez de SQL (ROADMAP "Futuro") ficaram bem mais
fáceis com o Postgres, mas misturá-las com a troca de engine tornaria impossível saber o que quebrou.
