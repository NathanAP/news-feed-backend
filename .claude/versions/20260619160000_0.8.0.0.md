# v0.8.0.0 — Bruno collection

## What was done
Added a Bruno API collection to the project, allowing all current routes to be tested
directly from the Bruno app without manual setup.

### New files: `bruno/`
- `bruno/bruno.json` — collection metadata (name, version, type).
- `bruno/environments/local.bru` — local environment with `baseUrl`, `refreshToken`,
  `refreshTokenId`, `userId`, and `accessToken` (marked as secret so it is not
  displayed in plain text in the UI).

### Requests
| File | Method | Route |
|------|--------|-------|
| `health.bru` | GET | `/v1/health` |
| `auth/google-login.bru` | GET | `/v1/auth/google` |
| `auth/refresh-token.bru` | POST | `/v1/auth/refresh` |
| `auth/logout.bru` | POST | `/v1/auth/logout` |
| `auth/invalidate-session.bru` | DELETE | `/v1/auth/invalidate` |
| `auth/invalidate-all-sessions.bru` | DELETE | `/v1/auth/invalidate-all` |
| `users/me.bru` | GET | `/v1/users/me` |

### Usage
Open the collection in Bruno via **File → Open Collection** and point to the `bruno/`
folder. Select the **local** environment. After logging in via the browser, paste the
`access_token` and `refresh_token` into the environment variables to use authenticated
routes.

## Key decisions
- The `google-login.bru` request includes a `docs` block explaining it must be opened
  in a browser rather than executed directly from Bruno (OAuth2 requires a redirect flow).
- Environment variables committed with empty values — tokens are filled locally and
  never committed.
- `accessToken` is declared as a secret variable in Bruno to prevent it from being
  displayed in logs or stored in plain text.
