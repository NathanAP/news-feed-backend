# Versão 0.23.0.0 — detecção de idioma + tradução personalizada

**Data:** 2026-07-02

Adiciona a **tradução personalizada de notícias** sob demanda e a **detecção do idioma original** no
tratamento. É a primeira feature de IA **on-demand e por-usuário** (as anteriores eram batch na CRON),
então tem um desenho diferente: gatilho pelo usuário, leitura das preferências direto do JWT, e nada
persistido (o client cacheia). O **resumo** foi adiado (depende de Redis; ver ROADMAP).

## Decisões de planejamento (fechadas antes de codar)

- **Detecção de idioma NÃO é IA**: usa `lingua-go` (offline, determinístico, sem quota), então
  independe de provider/modo. Isso derrubou a dúvida "groq/ollama conseguem detectar?".
- **Tradução é LLM-only** (Gemini→Claude no futuro): SLM não dá conta. Sem mapa de modos — só
  `TRANSLATION_*`, espelhando `TREATMENT_*`.
- **Sem Redis / sem cache de servidor** nesta versão: cache é responsabilidade do client (Redis fica
  para o futuro). Isso manteve o escopo pequeno.
- **Enum de idiomas único**: `pt, en, es, fr, de, it` — o mesmo conjunto na preferência do usuário, no
  `language_original` do artigo e na detecção do `lingua-go`. `ja`/`zh` removidos para alinhar os três.
- **Camada única (sem locale)**: `pt` cobre BR e PT. O `lingua-go` não distingue variantes, então
  locale (pt-BR/pt-PT) tornaria `language_original` impreenchível. Se um dia quiser, entra como um
  `region` separado, não explodindo o enum.

## Principais mudanças

### Enum de idiomas global
- `schemas/language.go` (novo): `Language` movido de `user_preferences.go` para uma fonte única,
  compartilhada por preferências, artigos e tradução. `ja`/`zh` removidos; `DisplayName()` adicionado
  (ISO → nome em inglês para o prompt).

### Detecção de idioma (`services/langdetect`)
- Pacote novo: wrapper fino sobre `lingua-go`, restrito aos 6 idiomas suportados, com modelos
  pré-carregados. Strippa o HTML (bluemonday StrictPolicy) antes de detectar para as tags não
  enviesarem o resultado. Retorna código ISO minúsculo + `ok`; `("", false)` quando não confiável.

### `language_original` no artigo
- Migração `add_language_original_to_articles` (rebuild da tabela para manter a ordem de colunas
  alinhada ao sqlc; sem backfill). Coluna `TEXT` **nullable** (null quando a detecção falha).
- `schema.sql`, `sqlc` (models/queries/`articles.sql.go`) e `ArticleController.Create/Update`
  atualizados (parâmetro `languageOriginal *string`, helper `nullString`).
- **CRON**: o `TreatmentProcessor` detecta o idioma no conteúdo cru e grava junto do artigo.
- **Criação/edição manual**: `language_original` é **obrigatório** no payload e validado contra o enum
  (400 se faltar/inválido) — a rota manual não passa pelo tratamento, então o admin informa.
- Dry-run `POST /articles/treatment` agora também detecta e devolve `language_original`.
- `ArticleResponse` passou a expor `language_original` (null quando desconhecido).

### Tradução (`ai.Translator` + rota)
- Capacidade `ai.Translator` no seam (adicionada ao `Client`), com `ParseTranslation` compartilhada,
  decorator `NewVerboseTranslator`, e impls em `gemini`/`openaicompat`. Prompt `article_translation`
  (traduz título+conteúdo+keywords, preserva HTML, adapta o tom à `ai_personality`, proíbe resumo/
  opinião, devolve JSON).
- `GET /v1/articles/{id}/translate/{language}`: lê `translate_content`/`ai_personality` do JWT; **403**
  se o usuário não estiver apto; valida idioma-alvo (400); carrega o artigo (404); **400** se o
  `language_original` for null ou igual ao alvo; traduz; **re-sanitiza** a saída com o `bluemonday` do
  tratamento; responde `{ title, content, keywords, language, language_original }`. **Não grava nada**
  (read-only); o client cacheia. LLM-only via `TRANSLATION_*`.

### Wiring (`main.go`)
- `detector := langdetect.New()` injetado no processor e no dry-run de tratamento.
- `translator` (LLM via `TRANSLATION_PROVIDER/MODEL`, verbose por `TRANSLATION_VERBOSE_MODE`) na rota.

## Testes
- **Unit**: `ParseTranslation` (`services/ai`), `langdetect` (pt/en/es reais + strip de HTML +
  vazio→not ok), rota de tradução (sucesso, 403 gate, idioma inválido, 404, `language_original` null,
  mesmo idioma, falha de IA, sem auth), validação de `language_original` no create.
- **Integração**: rota de tradução com DB real (sucesso, mesmo idioma, idioma null, 404, sem auth);
  processor gravando `language_original` detectado e `null` na falha de detecção.
- **E2E**: sem e2e para a rota de tradução (regra e2e não permite mock de IA, só OAuth2) — mesmo
  precedente do tratamento/julgamento. Bodies de create/update dos e2e/integração ajustados para o
  novo campo obrigatório.
- `go vet ./...` limpo e `go test ./...` sem falhas (47 pacotes).

## Dependência
- `github.com/pemistahl/lingua-go` (detecção de idioma offline).

## Como testar
- **Tradução (Bruno)**: `Translate Article` — precisa de um artigo com `language_original` preenchido
  (via CRON, ou criando manualmente com o campo) e o usuário com `translate_content=true`. Troque o
  path `:language` para ver a saída em cada idioma; peça um idioma == original para ver o 400.
- **Detecção (Bruno)**: `Article Treatment (dry-run)` agora traz `language_original` no retorno.
- **Automatizado**: `task ta` (ou `go test ./...`).

## Observações / limitações
- Notícias criadas antes desta versão (se existissem) teriam `language_original` null → intraduzíveis.
  Como o banco é zerado, não há impacto.
- A regra "não resumir / não opinar" na tradução é inforçável no modelo (mesmo caso do tratamento) —
  é o que os guardrails futuros vão cobrir.
- Resumo (0.24 antiga) foi reposicionado no ROADMAP: a próxima versão é o comando `create-default`
  de seed; o resumo volta quando o Redis entrar.
