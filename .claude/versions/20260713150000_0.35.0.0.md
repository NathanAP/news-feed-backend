# Versão 0.35.0.0 — tratamento de notícias, Fase 2: tratamento de URLs (linking)

**Data:** 2026-07-13

Segunda fase da reforma do tratamento (0.34 Fase 1 · **0.35 URLs** · 0.36 embeds). Introduz o passo
**determinístico** que faz notícias apontarem umas para as outras: quando o corpo de uma notícia nova
tem um link cuja `url_original` **exata** já existe no nosso banco, esse link passa a apontar para o
**nosso client** (`CLIENT_URL/articles/{id}`) em vez da fonte externa.

## Pipeline

`dedup → langdetect(cru) → **url treatment** → sanitize → keywords → persist → judge`

O tratamento de URLs roda **antes** da sanitização (o link interno reescrito precisa existir antes do
`bluemonday`; como o bluemonday já permite links `http(s)`, **nenhuma mudança de política** foi
necessária).

## Novo pacote `services/urltreatment`

- **DB-agnóstico e testável:** o pacote só parseia/reescreve HTML; o acesso ao banco é **injetado** por
  um `Resolve func(ctx, hrefs []string) (map[string]string, error)` (segue a convenção de transações —
  quem toca no banco é o chamador).
- `Treat(ctx, content, resolve, verbose)`: parseia o corpo como fragmento (`x/net/html` +
  `ParseFragment` com contexto `body`, pra não injetar `<html>/<head>/<body>`), coleta os hrefs
  **únicos** dos `<a>`, chama `resolve` **uma vez**, reescreve só os que casaram e re-renderiza.
- **Best-effort:** erro de parse/resolve/render → devolve o **conteúdo original** (mais o erro, pra log).
  Nunca derruba o artigo.
- Escopo **só `<a href>`** (não texto solto nem `<img>`).

## Integração

- **`services/discovery/processor.go`** — novos campos `clientURL`/`urlVerbose`; método
  `resolveInternalURLs` (1 transação de leitura por artigo, loop `FindByURLOriginal`, ignora
  `ErrArticleNotFound`); no `processOne` roda o `Treat` entre langdetect e sanitize (pulado se
  `clientURL == ""`; erro → corpo original).
- **`services/endpoints/v1/articles/treatment.go`** (dry-run) — passou a receber `articleCtrl`, `runTx`,
  `clientURL`, `urlVerbose` e roda o **mesmo** tratamento de URLs (leitura no banco; continua sem gravar).
  `treatment_ms` agora cobre url treatment + sanitize.
- **`main.go`** — carrega `CLIENT_URL` (trim da barra final; aviso no boot se vazio) e
  `URLS_TREATMENT_VERBOSE_MODE`; injeta nos dois pontos.
- **`go.mod`** — `golang.org/x/net` promovido a dependência direta (`go mod tidy`).

Sem pré-filtro por source e sem query nova no `sqlc` (reusa `FindByURLOriginal`, índice único). Sem
mudança de schema.

## Decisões (fechadas com o Nathan)

- Link interno **absoluto** via `CLIENT_URL` (futuro: newsletter/compartilhamento precisam de URL absoluta).
- **Sem** pré-filtro por source (lookup direto por `url_original`; com índice, é barato — no Postgres, trivial).
- `CLIENT_URL` vazio → **pula + avisa** (app não quebra).
- Erro de banco no resolve → **não-fatal** (corpo original segue).

## Comportamentos aceitos

- Link para artigo do **mesmo batch** (ainda não persistido) ou **auto-link**: não casa `url_original`
  → não reescreve. Não-retroativo, aceitável.
- **Match exato** de `url_original` (sem normalização de query/barra) — conservador.

## Como testar manualmente (dá pra ver "de verdade")

1. `ENVIRONMENT=development` com `CLIENT_URL` setada (ex.: `http://localhost:5173`); `task ls`; `task sdfull`.
2. Garanta que existe uma notícia nossa com uma `url_original` conhecida (o `sdfull` semeia algumas; ou
   crie via `POST /v1/articles/create`).
3. `POST /v1/articles/treatment` com um `content` contendo `<a href="{aquela_url_original}">...</a>` e um
   link externo: a resposta mostra o link interno reescrito para `CLIENT_URL/articles/{id}` e o externo
   intacto. Requisição pronta no Bruno (`articles/treatment`).
4. (fim-a-fim) Rode a CRON numa source real cujas notícias se referenciem: no `sqlite-web`, o
   `articles.content` da notícia nova aponta para o nosso client quando referencia uma que já temos.
