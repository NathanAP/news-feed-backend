# Versão 0.25.0.0 — comandos de seed de desenvolvimento + dev-login

**Data:** 2026-07-03

Cria os utilitários de **desenvolvimento** para popular o banco sem depender da CRON, além do login
do usuário dev sem Google OAuth. Tudo restrito a `ENVIRONMENT=development`.

## `cmd/seed` — binário único com subcomando

- Um binário (`cmd/seed`) com dispatcher por subcomando (`main.go`), lógica por comando em
  `dev_*.go`, helpers em `seed.go` (guard de ambiente, raiz via `go.mod`, abertura+migração do DB,
  `report`) e loader de `examples.json` (`examples.go`).
- Escreve **através dos controllers da API** (mesmas regras: UUID v7, encode de keywords, limite de
  feeds, cascades). Acha a raiz do projeto e roda as migrações, então funciona em banco zerado.
- `cmd/seed/Taskfile.yaml` (incluído com `flatten` pelo Taskfile raiz) expõe cada subcomando como um
  `task` rodável da raiz. O include é **`optional: true`**: como o CI/CD apaga `cmd/` em staging/prod,
  sem isso o Task falharia ao carregar o Taskfile inteiro lá; com isso, o include é simplesmente
  ignorado quando ausente e o resto do Taskfile continua funcionando (verificado).

### Comandos
| task (alias) | subcomando | comportamento |
|---|---|---|
| `sud` | `user` | cria usuário dev + preferências (idempotente) |
| `sdl` | `login` | imprime `access_token` + `refresh_token` do usuário dev |
| `sds` | `sources` | cria sources (idempotente) |
| `sda` | `articles` | cria artigos (re-executável, `url_original` aleatória por run; exige sources) |
| `sdf` | `feeds` | cria feeds do usuário dev (idempotente) |
| `sdaf` | `articles-feeds` | liga cada artigo a cada feed do dev, ignorando julgamento (idempotente) |
| `sdfull` | `full` | roda tudo em ordem + login |

Comandos idempotentes **pulam** o que já existe e reportam criados vs. pulados. Os artigos são
ligados round-robin às sources existentes no banco (não a ids do JSON).

## Login do usuário dev (sem OAuth)

- **Identidade fixa**: `schemas.DevUserGoogleID` (`google_id` do usuário dev) — compartilhada entre o
  seed (cria) e o dev-login (encontra), o que torna o seed idempotente e o login inequívoco.
- **CLI**: `task sdl` (comando `login`) imprime os tokens.
- **HTTP**: `POST /v1/users/dev-login` — emite `{ access_token, refresh_token, expires_in }`.
  **Registro condicional** no `main.go`: só existe quando `ENVIRONMENT=development` (defesa em
  profundidade — a rota literalmente não existe em staging/prod, onde a pasta `cmd/` também é apagada
  pelo CI/CD). 404 se o usuário dev não foi semeado.

## Segurança
- Todo comando de seed recusa rodar fora de `development` (guard no `seed.go`).
- A rota `dev-login` só é montada em `development`.
- Validação de enums das preferências no seed do usuário: valor inválido em `examples.json` (ex.:
  `ai_personality: "friendly"`, que foi corrigido para `mixed`) falha claro em vez de gravar lixo.

## Testes
- `cmd/seed/seed_test.go`: cada comando contra DB em memória — criação + idempotência (user/sources/
  feeds/articles-feeds), pré-requisitos com erro claro (articles exige sources; feeds/articles-feeds/
  login exigem o dev user), re-execução de artigos, validação de enum inválido, login mintando token.
- `tests/integration/api/users/dev_login_test.go`: endpoint dev-login (200 com tokens; 404 sem
  usuário dev).
- `go vet ./...` limpo e `go test ./...` sem falhas (50 pacotes). Smoke test real do `sdfull`
  validado localmente.

## Como testar
- `task sdfull` (com `ENVIRONMENT=development`) popula o banco e imprime um token no fim.
- Ou passo a passo: `task sud` → `sds` → `sdf` → `sda` → `sdaf` → `sdl`.
- No Bruno: `Dev Login (development only)` bate em `POST /v1/users/dev-login`.
