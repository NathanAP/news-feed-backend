# Versão 0.20.0.0 — tratamento de notícias (Gemini) + persistência + dedup por url_original

**Data:** 2026-06-30

## Resumo

Primeira integração com IA (Google Gemini). A descoberta deixa de ser dry-run: agora a CRON
descobre, **deduplica por `url_original`**, **trata** cada notícia nova com o Gemini (limpar o
conteúdo + nomear palavras-chave, em duas chamadas) e **persiste** o `article`. Inclui a rota de
teste `POST /v1/articles/treatment` (dry-run do tratamento) e renomeia duas rotas para a convenção
de `-`.

## Decisões aplicadas

- **Camada de IA atrás de interface (`services/ai`).** A app inteira depende de `ai.Client`
  (`Treat`, `Keywords`); só `services/ai/gemini` importa o SDK `google.golang.org/genai`. Trocar
  para LangChain/Claude no futuro = nova implementação da interface + uma linha no `main.go`.
- **Cliente desabilitável.** Sem `GOOGLE_API_KEY`/`PRIMARY_AI_MODEL`, `main` usa um
  `ai.NewDisabledClient()` (falha clara por chamada) em vez de abortar o boot — dev sem chave roda
  o resto da app normalmente.
- **Dedup por `url_original`** substitui o filtro de data. A data (`last_article_discovery_at`)
  continua sendo escrita pela CRON (informativa), mas não filtra mais. Custo aceito: a 1ª run trata
  o feed atual inteiro (pico único, limitado pelo tamanho do RSS).
- **Dedup ANTES de tratar** — não gasta chamada de IA com URL já existente.
- **Tratamento em duas chamadas** (`article_treatment` → conteúdo limpo; `article_keywords` sobre o
  conteúdo já tratado), conforme o "Fluxo de tratamento" do `PROJECT.md`. Saída validada (treat:
  markdown não-vazio; keywords: JSON, 5–20 distintas, tolera code fence).
- **Falha de IA → não persiste e re-tenta:** como nada é gravado, a notícia é redescoberta na
  próxima run (self-healing pelo dedup). Chamadas de IA ficam fora de transação; com retry/backoff
  e timeout de 60s.
- **Renomes** corrigem a convenção de `-`: `rss_discovery`→`rss-discovery`,
  `sources/:id/discovery`→`sources/:id/article-discovery`. A dry-run de `article-discovery` agora
  espelha a CRON (aplica o dedup `url_original` read-only).
- **Prompts via `go:embed`** num pacote `services/prompts` (mantém os `.yaml` onde a convenção
  manda e provider-agnósticos).

## O que foi feito

### Dependência

- `google.golang.org/genai`. `PRIMARY_AI_MODEL` no `.env` (default `gemini-2.5-flash`).

### IA / prompts

- `services/ai/ai.go` — interface `Client`, erros (`ErrEmptyTreatment`, `ErrInvalidKeywords`,
  `ErrDisabled`), `NewDisabledClient`.
- `services/ai/gemini/gemini.go` — impl Gemini (carrega prompts, gera, valida, retry/backoff/timeout).
- `services/prompts/prompts.go` — `go:embed *.yaml` + `Load`/`Render`.

### Descoberta / CRON

- `services/discovery/discovery.go` — `DiscoverFromSource` com `since` opcional (zero = sem filtro);
  removidos `EffectiveSince` e `NoopProcessor`.
- `services/discovery/processor.go` — `TreatmentProcessor`: dedup `url_original` → `Treat` →
  `Keywords` → `Create`. Logs gated por verbose.
- `services/cron/cron.go` — runner não filtra mais por data; usa o `TreatmentProcessor`.

### sqlc / controllers

- `FindArticleByURLOriginal` (query + `articles.sql.go` + querier) e
  `ArticleController.FindByURLOriginal` (+ interface).

### Endpoints / schemas

- `services/endpoints/v1/sources/article_discovery.go` — `GET /v1/sources/:id/article-discovery`
  (dry-run com dedup read-only).
- `services/endpoints/v1/articles/treatment.go` — `POST /v1/articles/treatment` (dry-run; chama IA;
  não persiste). Loga a causa real da falha de IA (`VERBOSE_MODE`) antes de responder 500 — sem
  isso, um 429 de billing do Gemini, por exemplo, ficava mascarado como "failed to treat article".
- `schemas` — `RawArticleInput`, `TreatArticleRequest`, `ArticleTreatmentResponse`,
  `DiscoveredArticleResponse`/`SourceDiscoveryResponse`.

### main.go

- `buildAIClient()` (gemini ou disabled); `TreatmentProcessor` no scheduler; rotas renomeadas; rota
  de tratamento registrada.

### Testes

- Mock `tests/mocks/external/gemini_client.go` (`MockAIClient`).
- Unit: parsing de keywords do Gemini (`services/ai/gemini`, interno); rota de tratamento
  (200/400/401/500); `article-discovery` (itens/vazio/404/401/data inválida/erro de feed).
- Integração: `article-discovery` dry-run sem efeitos colaterais + dedup; runner da CRON
  (descobre + processa + avança watermark; pula com app off).
- E2E: fluxo de `article-discovery` dry-run.

### Bruno / controle

- `bruno/articles/treatment.bru`; renomeados rss/article-discovery. `.env.example`/`ROADMAP` →
  0.20.0.0; memory atualizada.
