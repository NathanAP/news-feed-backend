# Versão 0.16.0.0 — articles_feeds + mark-as-read

**Data:** 2026-06-29

## Resumo

Junction table `articles_feeds` ligando notícias a feeds, com o campo `is_read` para rastrear o estado de leitura por usuário. Inclui a rota `PUT /v1/articles/{id}/read` e o enriquecimento do `GET /v1/articles/{id}` com `is_read`. A invisibilidade de registros com pais soft-deleted é garantida por JOIN, sem tocar na junction.

## Decisões aplicadas

- **Sem desnormalização (`user_id`):** as queries acessam o usuário via JOIN com `feeds`. Documentado em `conventions.md` (linha 70).
- **Registros da junction permanecem no soft-delete dos pais:** invisibilidade garantida pelo JOIN (`feeds.status = 1 AND feeds.removed_at IS NULL`). Hard delete dos pais → hard delete da junction (futuro).
- **`MarkArticleAsReadForUser` idempotente:** `UPDATE ... WHERE is_read = 0` — já-lidos não são tocados.
- **200 vs 204 no mark-as-read:** 200 quando o usuário tem o artigo em pelo menos um feed (marcado ou já lido); 204 quando não tem nenhum feed associado.
- **`is_read` no `GET`:** sempre presente, nunca parametrizado. `null` = não está em nenhum feed; `false` = pelo menos um feed com `is_read = 0`; `true` = todos os feeds com `is_read = 1`.
