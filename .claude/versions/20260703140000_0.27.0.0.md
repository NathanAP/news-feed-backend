# Versão 0.27.0.0 — paralelismo da descoberta/tratamento/julgamento + prompt de keywords

**Data:** 2026-07-03

Duas frentes que servem o mesmo objetivo (throughput da descoberta de notícias):

1. **Paralelismo** do pipeline via worker pool interno de goroutines.
2. **Melhoria do prompt de keywords** para o Groq acertar o idioma (inglês) e nomes próprios.

## 1. Paralelismo (worker pool)

### Decisão arquitetural
- **Goroutines internas**, não container efêmero. O gargalo do pipeline é **latência de I/O de rede**
  (2-3 round-trips de IA por notícia), que se resolve com concorrência — não com mais containers.
  Container efêmero traria orquestração, build de imagem separada e coordenação de estado sem ganho
  sobre o mesmo teto (rate limit do provedor de IA).
- A fronteira foi desenhada para ser **future-proof sem programar o futuro agora**: o pipeline por
  artigo (`discovery.processOne`) não conhece quem o despacha. O pool in-process é o **caso de 1 nó** do
  modelo produtor + fila + workers. Migração pós-Postgres = troca de dispatcher, não reescrita. A visão
  distribuída ficou **arquivada** no `ROADMAP.md` (seção "Escalabilidade futura"), dependente do Postgres.

### `DISCOVERY_CONCURRENCY` (nova env)
- Governa **os dois pontos paralelos**: a varredura de RSS das sources e o pipeline por artigo.
- Default e mínimo `1` (sequencial). Dev/testes ficam em `1` → determinístico e sem interleave de logs.
  Staging/produção sobem o valor, limitado pelo rate limit da IA.
- Parse em `main.parseConcurrency` (fallback seguro para 1 quando inválido — não derruba o boot).
- Adicionada ao `.env.example` (bloco da CRON) e documentada em `PROJECT.md` ("Descobrindo uma notícia").

### `services/discovery/processor.go`
- Extraído `processOne(ctx, article)` do corpo do loop de `Process` (dedup → treat → keywords →
  langdetect → persist → judge).
- `Process` agora despacha os artigos para um **pool limitado** (semáforo com buffer =
  `concurrency` + `sync.WaitGroup`). Fast path sequencial preservado quando `concurrency <= 1` ou
  `len(articles) <= 1` (sem goroutines, ordem original mantida).
- Semântica preservada: falha por artigo é logada e engolida em `processOne`; `Process` nunca aborta o
  batch (sempre retorna `nil`). Cancelamento de `ctx` (shutdown) para de despachar e espera os em voo.
- **Concorrente-safe:** `processOne` não compartilha estado mutável; a dedup por `alreadyExists` +
  o índice único parcial de `url_original` colapsam duplicatas do mesmo batch para uma única linha
  (o insert perdedor recebe `ErrArticleAlreadyExists` e é descartado); cada escrita usa sua própria
  transação curta.
- Novo parâmetro `concurrency int` em `NewTreatmentProcessor`.

### `services/cron/cron.go`
- Varredura de sources paralelizada: novo `fetchAll(ctx, sources)` com o mesmo padrão de pool
  (append em `all` protegido por `sync.Mutex`). `fetchOne` isola a falha por source (uma feed ruim não
  aborta o sweep). Fast path sequencial quando `concurrency <= 1` ou `len(sources) <= 1`.
- Novo parâmetro `concurrency int` em `NewDiscoveryRunner`.

### `main.go`
- Lê `DISCOVERY_CONCURRENCY` uma vez (dentro do bloco `RSS_FEED_CRON_ACTIVE`) e passa para o
  `TreatmentProcessor` e o `DiscoveryRunner`. Nova const `defaultDiscoveryConcurrency = 1`.

## 2. Prompt de keywords (`services/prompts/article_keywords.yaml`)

Contexto: em testes reais o Groq (`GROQ_MODEL=qwen/qwen3-32b`) falhava em manter as keywords em inglês
(ex.: "Copa do Mundo" ficava em PT em vez de "world cup"). Um 32B tem o conhecimento — a instrução é que
não estava sendo ativada (enterrada numa lista, sem exemplos; possível preguiça de decoding com
`json_object` + `/no_think` copiando tokens do conteúdo em PT).

Mudanças no prompt (afeta todos os modos — local/groq/gemini usam o mesmo arquivo):
- Regra de inglês **front-loaded** como CRITICAL (não mais item nº1 no meio de uma lista).
- Regra explícita de **nomes próprios seletiva**: traduz entidades com forma consagrada
  (`Copa do Mundo`→`world cup`, `Alemanha`→`germany`), mantém nomes de pessoas/marcas
  (`Lula`, `Petrobras`, `Flamengo`).
- **3 exemplos few-shot multilíngues** (pt/es) mostrando conteúdo em outro idioma → keywords em inglês,
  incluindo um exemplo que demonstra manter e traduzir nomes na mesma saída.
- **Reforço no user message** (última coisa lida antes de responder).

Sem alteração de código do parser (`ai.ParseKeywords`) — comportamento do prompt não é testado por
convenção (só mocks); validação é empírica via `POST /v1/articles/treatment` (dry-run, `keywords_mode`).

## Testes

- `tests/integration/discovery/processor_test.go`: `setup` refatorado para `setupWithConcurrency`;
  call sites existentes passam `concurrency=1`. **Novos testes:**
  - `ConcurrentPersistsAllArticles` — 12 artigos distintos, pool de 4 workers → todos persistidos.
  - `ConcurrentDedupsWithinBatch` — mesma `url_original` 4× no batch com 4 workers → colapsa em 1 linha.
- `tests/integration/cron/discovery_test.go`: call sites passam `concurrency=1`. **Novo teste:**
  - `ConcurrentFetchCollectsAllSources` — 3 sources, sweep com workers=3 → todos os itens coletados.
- Suíte completa verde (`go test ./...`, exit 0). `-race` indisponível neste ambiente (SQLite é Go puro,
  CGO desabilitado); a segurança de concorrência foi garantida por design (mutex no append da CRON;
  `processOne` stateless) e o banco de teste tem `SetMaxOpenConns(1)` (transações serializam, sem
  deadlock).

## Como testar

- **Paralelismo:** `DISCOVERY_CONCURRENCY=4` no `.env` + CRON ativa (`RSS_FEED_CRON_ACTIVE=true`,
  `RSS_FEED_CRON_VERBOSE_MODE=true`) com várias sources cadastradas → observar nos logs a descoberta
  processando várias notícias em paralelo. Em dev, o default `1` mantém tudo sequencial.
- **Prompt do Groq:** `POST /v1/articles/treatment` com `keywords_mode=groq` e um `article` em
  português (com nomes próprios). Esperado: keywords em inglês (`world cup`, `brazil national team`) e
  nomes próprios preservados (`petrobras`, `lula`). Requer `GROQ_API_KEY` + `GROQ_MODEL`.

## Observações / pendências
- A validação empírica final do prompt é do usuário — ele vai medir em um servidor de homologação com
  volume real. O ganho isolado do Groq não pôde ser medido neste ambiente (sem chave/serviço).
- `DISCOVERY_CONCURRENCY` é um único knob para RSS e IA. Se um dia os limites ideais divergirem muito
  (RSS aguenta mais que a IA), pode-se separar em dois envs — não necessário agora.
