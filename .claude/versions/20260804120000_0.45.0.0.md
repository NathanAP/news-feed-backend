# 0.45.0.0 — Tabela de URLs externas de notícias (`article_outbound_links`)

## Resumo

Desacopla o **alvo** de um link no corpo de uma notícia do **corpo** em si. Cada `<a href>` de uma
notícia tratada deixa de carregar uma URL e passa a carregar o `id` de uma linha em
`article_outbound_links`; a linha guarda a URL real (interna ou externa). Ao servir uma notícia, o `id`
é trocado de volta pela URL (swap em tempo de leitura). Isso permite corrigir links entre notícias de
forma **retroativa** — quando a notícia B chega representando uma URL que a notícia A já linkava, só se
altera a linha da tabela, nunca o corpo (imutável) de A.

Fecha os três itens da 0.45 no ROADMAP: criar a tabela, ajustar as notícias às novas regras, e integrar
os passos de banco ao fluxo de tratamento.

## Modelo de dados

Nova tabela `article_outbound_links` (migração `20260804120000_article_outbound_links.sql`, espelhada em
`schema.sql` no fim, por causa do `SELECT *`):

- `id`, `article_id` (FK→articles), `href`, `created_at`, `modified_at`.
- **Sem** `status`/`removed_at` (exceção já registrada em `conventions.md`): são ponteiros de uma
  notícia, não registros soft-deletáveis.
- Índices: `article_id` (swap de leitura em batch) e `href` (retarget e limpeza por match exato).
- Cascade é **hard-delete por `article_id`** (espelha um hard-remove de notícia). **Dormente hoje** —
  notícias só sofrem soft-remove — mas pronta no código, na filosofia de cascade do projeto.
- **Sem backfill**: a tabela nasce vazia. Notícias gravadas antes da 0.45 mantêm URLs reais no corpo; o
  swap só troca `href` que casa com um `id` de outbound, então href legado (não-id) passa intacto. Um
  reseed limpo já move o dev para o novo formato.

## `href`: token `{CLIENT_URL}`

Links **internos** são gravados no `href` como o **token literal** `{CLIENT_URL}/articles/{id}` (não a
URL expandida). Assim, trocar o domínio do client é mudar uma env, não migrar dados — o swap de leitura
expande o token. Links **externos** são gravados literalmente.

**Invariante-chave** (a razão de o token e o `id` nunca poderem passar pelo bluemonday): nenhum deles é
uma URL válida, então o bluemonday apagaria o `href`. Por isso: `Assign` roda **depois** do sanitize; o
swap (`Resolve`) roda **antes** de qualquer re-sanitização (na tradução, o `Resolve` acontece antes de
mandar o corpo para a IA, cujo output é que é re-sanitizado — já com URLs reais).

## Serviço `services/outboundlinks`

Pacote de lógica pura (sem banco; o caller injeta a persistência e a transação), com teste co-localizado:

- `Assign(content, clientURL, newID)` — acha cada `<a href>` **distinto**, atribui um id novo, reescreve
  o anchor para carregar o id, e devolve os `[]Link{id, href}` a persistir (interno→token, externo→literal).
  **Uma linha por href distinto**: anchors idênticos compartilham o id e são corrigidos juntos na
  retroatividade.
- `Resolve(content, byID, clientURL)` — troca `id`→`href` e expande o token. Href desconhecido (corpo
  legado, ou id fora do map) passa intacto. Best-effort em erro de parse/render.
- `InternalHref(articleID)` — fonte única do formato-token, usada pelo retarget.

## Fluxo de tratamento (etapa "Operações no banco de dados")

`discovery/processor.go` — o `persist` virou **uma transação** sequencial com os passos da 0.45:

1. **Gravação**: salva a notícia (corpo ainda com URLs reais).
2. **Associação + Reorganização**: `Assign` sobre o corpo, cria as linhas outbound, e grava o corpo em
   forma-id de volta (`UpdateArticleContent`). Best-effort dentro da tx — falha de parse mantém o corpo
   com URL real e nenhuma linha (o `Resolve` deixa href não-id em paz), então perde-se o rewrite mas não
   a notícia.
3. **Alteração**: `Retarget(url_original, InternalHref(id))` — notícias antigas que apontavam para a URL
   externa desta notícia passam a abri-la internamente. No-op quando nada casa; o token adia o
   `CLIENT_URL` para a leitura, então roda mesmo sem `CLIENT_URL` configurada.

Uma falha de escrita de banco em qualquer passo faz rollback do bloco (a notícia é redescoberta depois).
O julgamento continua **fora** dessa transação, como antes.

## Endpoints de leitura (swap centralizado)

Passam a receber `outboundCtrl` + `clientURL` e resolvem o corpo antes de responder:

- `GET /v1/articles/{id}` — busca outbound de 1 notícia.
- `GET /v1/articles` e `GET /v1/feeds/{id}/articles` (paginados) — **um batch** dos outbound da página
  inteira (`ListByArticleIDs`, ids globais → um único map resolve tudo), sem N+1.
- `GET /v1/articles/{id}/translate` — resolve **antes** de mandar para a IA (invariante acima).

Decisão aceita: o custo de leitura subiu (parse+rewrite de HTML por notícia, por resposta, no caminho
mais quente da app) — troca deliberada de custo-de-escrita-única por retroatividade. Sem Redis ainda,
não há cache; fica para o futuro.

## Fora de escopo / notas

- **Create/Update de admin** (escape hatch) inserem conteúdo cru, **não** passam pelo pipeline, então não
  têm linhas outbound e o swap é no-op para eles. Consequência aceita: notícia criada por admin não
  participa da linkagem retroativa (nem de/para ela). Documentado.
- **`POST /v1/articles/treatment` (dry-run)** para **antes** do bloco de banco (é escrita, não cabe em
  dry-run): devolve conteúdo com URLs reais, não a forma-id que o corpo gravado teria. O bloco novo é
  coberto pelos testes de integração de discovery.
- **Limpeza pré-remoção** (reverter `{CLIENT_URL}/articles/{id}` → `url_original` de outras notícias antes
  de remover uma) está escrita no `PROJECT.md` e a query `Retarget` já a suporta; como não há endpoint de
  remoção que exercite isso além do soft-delete de admin, foi deixada pronta mas não cableada num
  gatilho de remoção nesta versão (mesma postura de "cascade pronto no código").
- **`mailto:`/externos**: viram linha outbound como qualquer anchor; nunca casam com uma `url_original` e
  o `Resolve` os restaura idênticos — inócuos.
- **Fragilidade futura anotada**: toda a identidade de link interno depende de `CLIENT_URL`. O token
  resolve a troca de domínio, mas mudanças no *path* (`/articles/{id}`) exigiriam atenção.

## Seed

`cmd/seed/dev_articles.go` espelha o passo outbound: cada artigo de exemplo (os 20 têm `<a href>`) grava
corpo em forma-id + linhas outbound (os links de exemplo são externos → literais). Sem isso, o dev não
exercitava o swap.

## Como testar

1. Docker ligado. `task dp` (limpa o volume) → `task dbs` → `task sdfull`.
2. Inspecionar no pgAdmin: `articles.content` de um artigo de exemplo tem `href="<uuid>"`; a tabela
   `article_outbound_links` tem as linhas correspondentes.
3. `GET /v1/articles/{id}` (Bruno) — a resposta traz o `content` com as URLs reais de volta.
4. `task ta` (suíte completa; exige Docker).
