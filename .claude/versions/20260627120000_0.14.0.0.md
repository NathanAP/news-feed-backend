# Versão 0.14.0.0 — source_id em articles

**Data:** 2026-06-27

## Resumo

Ligação obrigatória entre cada notícia e a fonte de onde ela veio. Adiciona a coluna `source_id` (NOT NULL, FK para `sources`) na tabela `articles`, exigida na criação e **imutável** depois. Toda a complexidade foi o ripple sobre o domínio `articles` já existente (0.13).

## Decisões aplicadas (documentadas pelo usuário)

- `source_id` **obrigatório** no create (PROJECT.md 151).
- `source_id` **imutável**: a rota de edição não o altera (PROJECT.md 152).
- Sem tratamento retroativo: o banco foi resetado, então a coluna nasce `NOT NULL`.

## O que foi feito

### Banco de dados
- `migrations/20260627120000_add_source_id_to_articles.sql` — **rebuild** da tabela `articles` para adicionar `source_id TEXT NOT NULL REFERENCES sources(id)`.
    - Motivo do rebuild: o SQLite rejeita `ALTER TABLE ADD COLUMN ... NOT NULL` sem `DEFAULT`. Com a tabela vazia (banco resetado), a cópia é trivial.
    - O índice único parcial `idx_articles_url_original_active` é recriado após o rebuild.
    - `down` reverte para a tabela sem `source_id`.
- `schema.sql` — `articles` ganha `source_id TEXT NOT NULL REFERENCES sources(id)`.

### SQLC
- `sqlc/models.go` — `Article` ganha `SourceID string`.
- `sqlc/queries/articles.sql` + `sqlc/articles.sql.go` — `source_id` no INSERT, em `CreateArticleParams`, e em todos os SELECT/RETURNING/scan. O `UpdateArticle` lê `source_id` no retorno mas **não** o altera (imutável).

### Controller
- `services/controllers/articles.go`:
    - `Create` ganha o parâmetro `sourceID` e valida, dentro da transação, que a fonte existe e está ativa via `q.FindSourceByID` (que já filtra `status = 1 AND removed_at IS NULL`). Fonte inexistente/inativa → novo erro tipado `ErrArticleSourceInvalid`.
- `services/controllers/interfaces.go` — assinatura de `Create` atualizada na `ArticleControllerInterface`.

### Schemas
- `schemas/articles.go`:
    - `CreateArticleRequest` ganha `source_id` (obrigatório).
    - `UpdateArticleRequest` **não** tem `source_id` (imutável).
    - `ArticleResponse` ganha `source_id`.

### Endpoints
- `services/endpoints/v1/articles/create.go`:
    - Valida `source_id` não-vazio → **400** ("source_id is required").
    - Mapeia `ErrArticleSourceInvalid` → **400** ("source not found or inactive").
    - `toArticleResponse` inclui `source_id`.
- `update.go` inalterado (não toca `source_id`).
- `main.go` sem mudança (a validação da fonte é interna ao controller).

### Testes (o grosso do trabalho)
- `tests/fixtures/article_fixtures.go` — fixtures de article passam a referenciar `NewTestSource().ID`.
- **Unit**: mock e `validCreateBody` com `source_id`; novos casos — falta de `source_id` → 400, `ErrArticleSourceInvalid` → 400, `source_id` presente na resposta.
- **Integração**: novo helper `seedSource` (insere a fonte via `queries`); todos os creates passam a semear uma fonte; novos casos — fonte inexistente → 400, fonte inativa (soft-deleted) → 400, `source_id` imutável no update.
- **E2E**: o app de teste passa a registrar `POST /v1/sources/create`; novo helper `createSourceViaAPI` cria a fonte pelo endpoint real antes do article; o fluxo CRUD valida `source_id` na resposta e a imutabilidade no update; nova validação "missing source_id".

### Bruno
- `bruno/articles/create-article.bru` — body com `source_id` (`{{sourceId}}`) e doc atualizada (obrigatório, imutável, 400/409).

## Resultado dos testes

`go vet` limpo e suite completa passando (todos os domínios).
