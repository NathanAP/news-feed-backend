# Versão 0.33.0.0 — preferências enxutas (tema fora, tradução colapsada)

**Data:** 2026-07-13

Reforma nas preferências de usuário. Sai o `theme` (vira responsabilidade do client via
localStorage) e o `language` vira `language_to_translate` **anulável**. No caminho, uma decisão de
modelo: o `translate_content` foi **removido**, colapsado no próprio `language_to_translate`
nulo/preenchido.

## Decisão de modelo (fechada com o Nathan)

O roadmap pedia só "renomear `language` → nullable". Mas com `language_to_translate` podendo ser nulo
e "nulo = client não mostra a opção de tradução", esse campo passou a significar exatamente o que o
`translate_content` já significava (opt-in de tradução) — dois campos para o mesmo conceito.

Escolhida a **Opção A (colapsar)**:

- `translate_content` **deixa de existir** (tabela, DTOs, `Claims`, controller, seed, Bruno).
- `language_to_translate` anulável é o **único knob**: `null` = tradução off (client esconde a opção);
  preenchido = idioma-alvo. Default `pt`.
- A tradução vira **capacidade read-only sem gate de preferência** no servidor. A preferência é apenas
  **dica de client** e **não afeta nenhuma resposta da API** (`PROJECT.md`).

`theme` era dado puro de passthrough (nunca usado em lógica), então a remoção foi limpa.

## Banco de dados

- Migração `20260713120000_drop_theme_translate_content_nullable_language.sql`: como o SQLite não altera
  constraint de coluna in-place, é um **rebuild de tabela** — cria a nova `user_preferences` (sem
  `theme`/`translate_content`, com `language_to_translate TEXT` nullable), copia os dados
  (`language` → `language_to_translate`), dropa a antiga e renomeia. O `down` reverte, recriando
  `theme` (`'dark'`), `translate_content` (`1`) e `language` NOT NULL (`COALESCE(...,'pt')`).
- `up`/`down`/`up` validados em DB in-memory (goose) além de rodarem em todos os testes de
  integração/e2e (o `SetupTestDB` aplica as migrações de verdade).
- `schema.sql` espelhado; `sqlc generate` regenerou `models.go` e `user_preferences.sql.go`
  (`LanguageToTranslate sql.NullString`).

## Código

- **Enum**: `schemas/enums/theme.go` removido.
- **Controller** (`user_preferences.go`): `UpdatePreferencesParams` agora é `{ LanguageToTranslate
  *enums.Language, AIPersonality }`; default `language_to_translate=pt`; novo helper
  `LanguageToTranslatePtr(prefs)` (sql.NullString → *enums.Language) reusado no token e nas respostas.
- **Claims/JWT** (`schemas/auth.go`, `controllers/auth.go`, mock `tests/mocks/services/jwt.go`): token
  passa a carregar `language_to_translate` (anulável) + `ai_personality`; sai `theme`, `language`,
  `translate_content`. Tokens antigos seguem válidos (campos ausentes viram zero-value; trecho não
  crítico).
- **DTOs** (`schemas/user_preferences.go`): request/response com `LanguageToTranslate *enums.Language`
  (serializa `null`) + `AIPersonality`.
- **Endpoints**: `get_preferences.go`/`update_preferences.go` ajustados (validação do idioma só quando
  presente); `articles/translate.go` **perde o gate** `!translate_content || language==""` (403
  removido) — passa a validar só idioma-alvo, artigo existente e regras de `language_original`.
- **Seed** (`cmd/seed/examples.go`, `dev_user.go`, `examples.json`): `language_to_translate` (`*string`
  para permitir null) + `ai_personality`.

## Testes

- Preferências (unit + integração + e2e): asserts migrados para `language_to_translate`/`ai_personality`;
  removidos casos de `theme`; **novos casos** de `language_to_translate: null` (tradução off persiste).
- Tradução (unit): o antigo `GateDisabled` (403) virou **`NoPreferenceGate`** — prova que um usuário com
  `language_to_translate` nulo **ainda traduz** (sem gate no servidor). Integração de tradução inalterada.
- Fixtures/mocks e `transaction_test` (cascade user→prefs) atualizados.
- `go build`, `go vet`, `go test ./...` — **verdes** (suíte completa).

## Como testar manualmente

1. `ENVIRONMENT=development task ls` (ou `go run main.go`); `task sdfull` para semear e pegar um token.
2. `GET /v1/users/me/preferences` → `{ language_to_translate, ai_personality }` (sem `theme`/`translate_content`).
3. `PUT /v1/users/me/preferences` com `{"language_to_translate": null, "ai_personality": "mixed"}` →
   200; um novo `GET` mostra `language_to_translate: null`. Com `"en"`, volta preenchido.
4. `GET /v1/articles/{id}/translate/es` **funciona mesmo com `language_to_translate` nulo** (sem 403);
   só dá 400 se idioma-alvo == `language_original` ou `language_original` for null.
