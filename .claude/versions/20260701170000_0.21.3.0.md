# Versão 0.21.3.0 — refinos do tratamento (consolidado 0.21.1→0.21.3)

**Data:** 2026-07-01

Consolida todas as correções e refinamentos feitos **em cima da 0.21.0** (keywords via SLM) durante
os testes locais reais com Ollama/Groq/Gemini. Reúne o que eram os patches 0.21.1, 0.21.2 e 0.21.3.

## 1. Confiabilidade e idioma das keywords (era 0.21.1)

- **`/no_think` + JSON mode na SLM** (`openaicompat`): o qwen3 estava gastando tempo gerando o bloco
  de "thinking" (lentidão em CPU) e às vezes devolvia prosa em vez de JSON (erro `invalid character`).
  Agora injetamos `/no_think` e forçamos `response_format: json_object` na etapa de keywords.
- **Keywords em inglês + minúsculas**, aplicado no **único ponto de gravação**
  (`controllers.encodeKeywords` → trimmed lowercase, vale pra articles e feeds) + na
  `ai.ParseKeywords` (pro dry-run refletir o salvo) + no prompt.

## 2. Modos de keywords + benchmark via Bruno (era 0.21.2)

- **`KEYWORDS_MODE`** seleciona o backend: `local` (Ollama qwen3:4b), `groq` (Groq, SLM hospedado) ou
  `gemini` (LLM). `main.buildKeyworders` pré-monta os três no boot (`OLLAMA_BASE_URL`; `GROQ_API_KEY`
  + `GROQ_BASE_URL` + `GROQ_MODEL`; `GOOGLE_API_KEY` + gemini-2.5-flash).
- **`openaicompat` ganhou API key** (`Authorization: Bearer`) — local dispensa, Groq usa. Groq é
  OpenAI-compatible, então reusa o mesmo cliente.
- **Rota de teste turbinada** (`POST /v1/articles/treatment`): body aceita `keywords_mode` opcional,
  que troca o backend **só naquela chamada** (benchmark sem reiniciar; 400 se o modo não existir). A
  resposta traz `keywords_mode`, `treatment_ms` e `keywords_ms`.
- **Fix:** o `openaicompat` montava `/v1/v1/chat/completions` quando a base já terminava em `/v1`
  (caso do Groq). Agora tolera base com ou sem `/v1` (teste de regressão).

## 3. Saída HTML + sanitização (era 0.21.3)

- **Tratamento agora sai em HTML básico** (antes Markdown): prompt pede só
  `<p>/<strong>/<em>/<ul>/<ol>/<li>/<blockquote>/<h2..h4>`, sem links, imagens, wrappers nem
  `class`/`style`.
- **`services/sanitize`** com **bluemonday**, aplicado como decorator no `Treater` (vale pra CRON e
  dry-run). Garante a whitelist independente do que o modelo cuspir — é a defesa real contra XSS.
- **Política customizada (NÃO `UGCPolicy`)**: a UGCPolicy permite `<a>`/`<img>`/URLs, o que contraria
  a regra do projeto. A nossa permite só tags básicas, sem atributos, sem links/imagens;
  `SkipElementsContent` em `script/style/head/title/noscript/iframe`. Documento HTML completo é
  tratado (remove wrappers, mantém o corpo).

## Dependência

- `github.com/microcosm-cc/bluemonday`.

## Resultado dos testes

`go vet ./...` limpo e `go test ./...` sem falhas.

## Limitação conhecida (em estudo)

- A regra "keywords sempre em inglês" **não é 100% obedecida** nem por modelos fortes: termos que
  parecem nome de entidade vazam no idioma original (ex.: "copa do mundo 2026", "bateria"). Reforçar
  o prompt com few-shot ajuda, mas o usuário optou por **não** forçar por exemplo agora. Estratégia
  provisória: **`groq` em dev / `gemini` em produção**, estudando o caso aos poucos. Isso reforça a
  decisão pendente da 0.22: se a aderência ao inglês não fechar, normalizar keywords de feed também
  pra inglês, ou confiar na camada 2 (IA) pro cross-idioma no julgamento.
